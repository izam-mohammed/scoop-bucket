# scoop-bucket: what every change passes

There is no single local command yet: the checks run only in CI, as steps
of `.github/workflows/check.yml`. `plans/01-quality-gates.md` lands
`sh scripts/check.sh` as the one command. A change is done when the
workflow is green on its pull request.

## Toolchain

| What | Version | Pinned in |
| --- | --- | --- |
| Python | runner's `python3` | not pinned (stdlib only) |
| check-jsonschema | 0.38.2 | `.github/workflows/check.yml` (`uvx check-jsonschema@0.38.2`) |
| uv | via `astral-sh/setup-uv` v10.3.0 | `.github/workflows/check.yml`, by commit SHA |
| jq, curl, sha256sum | runner's | not pinned |
| Scoop schema | `ScoopInstaller/Scoop` at `e6aa3b3` | `.github/schema/scoop-manifest.json` |

## Checks

| Check | Tool | Config | Command | Passing means |
| --- | --- | --- | --- | --- |
| Format | Python `json` | inline in `check.yml` | step "valid json, 4-space indent, trailing newline" | every top-level `*.json` is valid JSON, 4-space indent, one trailing newline |
| Schema | check-jsonschema | `.github/schema/scoop-manifest.json` | `uvx check-jsonschema@0.38.2 --schemafile .github/schema/scoop-manifest.json <manifests>` | every manifest matches Scoop's schema |
| Downloads | curl, jq, sha256sum | inline in `check.yml` | step "downloads exist and hashes match" | every `url` downloads and its sha256 equals the manifest's `hash` |
| Secret scan | none yet | | | `plans/01-quality-gates.md` |
| Dependency audit | not applicable | | | no dependencies: manifests point at release archives, whose hashes are checked |

## Tests

No program code, so no unit tests and no coverage floor. The checks
themselves are the tests of each manifest.

## Constraints

- Manifests are generated by GoReleaser in each app's repository and
  committed straight to `main` by the release bot. Never hand-edit one;
  fix the generator and release again.
- The format check matches the generator's output (4-space JSON), so a
  regenerated manifest passes unchanged.

## Conventions

- Commits: Conventional Commits with a scope where it helps
  (`ci:`, `docs(readme):`), lowercase subject, no attribution lines.
- Human changes reach `main` through a pull request; bot release commits
  are pushed directly.

## CI

`.github/workflows/check.yml` on every pull request and every push to
`main`, `contents: read` only, actions pinned by commit SHA,
`persist-credentials: false`.

## Decided

- `check-jsonschema` against a vendored copy of Scoop's schema, so the
  check never fetches the schema at run time (PR `#2`).
