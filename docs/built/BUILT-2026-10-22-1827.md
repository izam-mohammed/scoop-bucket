## In short

A Scoop bucket: Windows users add it with `scoop bucket add` and install
the apps it lists. It holds one manifest today, `claim.json`, written by
GoReleaser when the `claim-your-code` project releases (commit `743d6aa`,
authored by the release bot). Nothing here is built or run by hand; a
manifest changes when its upstream project ships.

## What a person can use

### Installing apps

- `claim` 0.1.0 installs from `claim.json`, 64-bit and arm64 Windows
  archives with their sha256 hashes (`claim.json`; commit `743d6aa`).

### Reading the repository

- The README opens with a light and a dark banner picked by the viewer's
  GitHub theme (`README.md`, `assets/banner-light.svg`,
  `assets/banner-dark.svg`; PR `#1`).

## Under the hood

- **Shape**: top-level `*.json` manifests, one per app, generated by
  GoReleaser in each app's own repository (`claim.json`).
- **Data**: none beyond the manifests.
- **Integrations**: GitHub release downloads named in each manifest's
  `url` fields; Scoop's manifest schema vendored at
  `.github/schema/scoop-manifest.json` from `ScoopInstaller/Scoop` at
  `e6aa3b3` (PR `#2`).
- **Standards and CI**: `.github/workflows/check.yml` runs on every pull
  request and push to `main`: JSON validity and the generator's 4-space
  format, the Scoop schema through `check-jsonschema` 0.38.2, and every
  download fetched with its sha256 compared to the manifest (PR `#2`).
  The logic lives inline in the workflow; there is no local check command
  and no `docs/standards.md` before this snapshot's commit.

## Unfinished or broken

- No secret scan, dependency audit, static analysis or workflow lint:
  the shared gate in `izam-mohammed/.github`
  (`.github/workflows/security-scan.yml`) is not called here, and there is
  no `.pre-commit-config.yaml` or `.github/dependabot.yml`.
- The checks cannot be run locally as one command: they exist only as
  steps in `.github/workflows/check.yml`.
- Release-bot commits land on `main` directly (commit `743d6aa`), so the
  check reports after the manifest is already published, not before.
- Nothing installs a manifest on Windows; that `claim` actually runs after
  `scoop install` is unverified.
- Not applicable here, by judgement: a `site/` one-pager (the bucket is a
  delivery channel; the app's own repository is where a site belongs) and
  a 90 % coverage floor (there is no program code, only generated data and
  CI glue; the check is proved by fixtures instead).
- README banner: already met (PR `#1`), so no plan is written for it.
